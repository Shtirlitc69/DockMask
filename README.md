# TriemaDeid

TriemaDeid — локальное Windows-приложение для обезличивания конфиденциальных данных в тендерных и сопутствующих документах. Оно принимает PDF, DOCX и XLSX, находит выбранные типы сущностей, заменяет их маскирующими маркерами и возвращает файл в исходном формате с визуальной подсветкой изменений. Вместе с результатом приложение выдаёт JSON-отчёт для ручной проверки.

Продукт рассчитан на договоры, коммерческие предложения, счета, акты и финансовые отчёты. Файлы и метаданные задач обрабатываются и хранятся на компьютере пользователя. Вызов LLM вынесен в сменяемый адаптер: GigaChat можно заменить локальной или OpenAI-совместимой моделью без изменения доменной логики.

## Возможности MVP

- Приём PDF, DOCX и XLSX и выбор типов данных для обезличивания.
- Извлечение текста и структуры документа, включая таблицы.
- Определение поставщика и покупателя, если в документе есть достаточные признаки роли.
- Поиск сущностей правилами и через LLM, объединение результатов и оценка уверенности.
- Замена найденных фрагментов маскирующими маркерами с сохранением исходного формата, где это позволяет формат документа.
- Визуальная подсветка каждого применённого изменения и отдельный JSON-отчёт.
- Уточняющие вопросы, когда системе не хватает данных для безопасной обработки.
- Локальная очередь задач с одним фоновым worker.

OCR для сканированных PDF — последующее, необязательное расширение после основного MVP. Оно использует тот же конвейер поиска и маскирования после распознавания текста.

## Как обрабатывается документ

1. Пользователь загружает файл, выбирает типы сущностей и при необходимости запрашивает OCR.
2. Экстрактор разбирает текстовые блоки и их расположение: абзацы и ячейки DOCX, ячейки и листы XLSX, блоки и координаты PDF.
3. Детекторы находят подходящие фрагменты; при наличии контекста определяется роль стороны — поставщик или покупатель.
4. Конвейер объединяет и проверяет результаты. При неоднозначности задача получает вопросы и переходит в состояние `needs_clarification`.
5. Редактор применяет согласованные замены, подсвечивает изменения и сохраняет обезличенный документ в исходном формате.
6. Сервис формирует отчёт о заменах. Пользователь скачивает документ и проверяет подсвеченные места вручную.

Это расширяемый последовательный конвейер с адаптерами, а не распределённая мультиагентная система: термин «AI-помощник» описывает продуктовую функцию, а не способ оркестрации процессов.

## Архитектура

```text
React 19 + TypeScript + Vite + Tailwind v4
                │ HTTP, только 127.0.0.1
                ▼
FastAPI + Uvicorn ── asyncio.Queue ── один фоновый worker
                │
     ┌──────────┼──────────┐
     ▼          ▼          ▼
  core/       llm/      storage/
конвейер,   адаптеры   SQLite и локальные
извлечение, моделей    каталоги задач
поиск, замены
```

- **Интерфейс.** React-приложение показывает состояние обработки, вопросы, настройки и ссылки на результаты. Русские подписи и тексты интерфейса формируются только во фронтенде; backend возвращает стабильные машинные значения.
- **Оболочка.** `pywebview` запускает локальный FastAPI-сервис и открывает интерфейс в WebView2.
- **Транспортный слой.** `app/` содержит FastAPI, Pydantic-схемы и зависимости. Он не содержит бизнес-правил.
- **Доменный слой.** `core/` не импортирует FastAPI и отвечает за извлечение, детектирование, определение ролей, редактирование и формирование отчёта.
- **Интеграции с моделями.** `llm/` реализует единый асинхронный контракт `AsyncBaseLLMClient`: `find_entities()` возвращает точные смещения сущностей, а `classify_party()` — роль стороны или отсутствие уверенного ответа.
- **Хранение.** `storage/` сохраняет метаданные задач в SQLite, а исходный файл и результаты — в локальных каталогах, изолированных по `job_id`.

## Технологии

| Слой | Технологии | Назначение |
| --- | --- | --- |
| Язык и API | Python 3.12, FastAPI, Uvicorn | Локальный HTTP-сервис на `127.0.0.1` |
| Контракты и конфигурация | Pydantic v2, pydantic-settings, platformdirs | Валидация API и расположение локальных данных |
| Асинхронность | asyncio, `asyncio.to_thread`, httpx.AsyncClient | Асинхронные запросы к LLM и вынос тяжёлой обработки документов в поток |
| Хранение | SQLite, aiosqlite | Метаданные задач, статусы и вопросы |
| DOCX | python-docx | Извлечение и замена текста с сохранением форматирования |
| XLSX | openpyxl | Маскирование строковых ячеек и подсветка изменённой ячейки |
| PDF | PyMuPDF (`fitz`) | Извлечение текста и настоящая redaction, а не прямоугольник поверх текста |
| PDF-таблицы | pdfplumber | Точечный анализ таблиц, когда PyMuPDF недостаточно |
| OCR, после MVP | Tesseract 5 с `rus` и `eng` tessdata | Распознавание сканированных PDF через `OCRProvider` |
| LLM | mock, GigaChat, OpenAI-compatible, Ollama, vLLM | Взаимозаменяемые реализации `AsyncBaseLLMClient` |
| Интерфейс | React 19, TypeScript, Vite, Tailwind CSS v4, pnpm | Единый локальный пользовательский интерфейс |
| Оболочка и сборка | pywebview, WebView2, PyInstaller | Windows-приложение; сначала `--onedir`, затем оценка `--onefile` |
| Качество | Ruff, pytest, pytest-asyncio, httpx, Vitest | Статический анализ, backend- и frontend-тесты |

Docker, Jinja2 и HTMX не входят в целевую архитектуру MVP. Для локального Windows-приложения контейнеры не нужны, а HTML-шаблоны не используются вместо React.

## Поддерживаемые данные

| Машинное значение | Данные |
| --- | --- |
| `person_name` | ФИО |
| `organization` | Наименование организации |
| `address` | Адрес |
| `amount` | Денежная сумма |
| `inn` | ИНН |
| `kpp` | КПП |
| `ogrn` | ОГРН |
| `phone` | Телефон |
| `email` | Электронная почта |
| `bank_account` | Банковский счёт |
| `bik` | БИК |
| `contract_number` | Номер договора |

Роли стороны: `supplier`, `buyer`, `unknown`.

Состояния задачи: `queued`, `processing`, `needs_clarification`, `done`, `failed`. Эти значения предназначены для кода; отображаемые пользователю русские статусы сопоставляет React-интерфейс.

Запись о найденном фрагменте содержит: `block_id`, `entity_type`, `text`, `start`, `end`, `replacement`, `source`, `confidence`, `party_role`. Смещения `start` и `end` относятся к тексту конкретного блока, а не ко всему файлу.

## HTTP API

Сервис доступен только на `127.0.0.1`. Все ответы, кроме скачивания файла, используют JSON. Идентификатор задачи — UUID.

### `POST /api/jobs`

Создаёт задачу обработки. Запрос `multipart/form-data`:

- `file` — исходный PDF, DOCX или XLSX;
- `entity_types` — один или несколько значений из справочника типов сущностей;
- `ocr_enabled` — логический флаг. В MVP для сканированных PDF не применяется и не должен создавать ложного ожидания поддержки OCR.

В ответе возвращаются `job_id`, `status: "queued"` и метаданные принятого файла.

### `GET /api/jobs/{id}`

Возвращает состояние и ход выполнения: `job_id`, `status`, `progress`, `questions`, `total_replacements`, `error`. В `needs_clarification` массив `questions` содержит идентификатор вопроса и текст, а `error` используется только для `failed`.

### `POST /api/jobs/{id}/answers`

Передаёт ответы на вопросы задачи:

```json
{
  "answers": [
    {"question_id": "uuid", "answer": "ООО «Пример» — поставщик"}
  ]
}
```

После валидации ответов задача возвращается в очередь обработки.

### `GET /api/jobs/{id}/document`

Скачивает обезличенный документ после статуса `done`. Формат совпадает с исходным. Для незавершённой задачи сервис возвращает ошибку состояния, а не неполный файл.

### `GET /api/jobs/{id}/report`

Возвращает JSON-отчёт после статуса `done`. Он содержит метаданные задачи, число замен, роли сторон при их определении и список применённых замен с исходным значением, маркером, источником, уверенностью и местоположением в документе.

### `GET /api/config`

Возвращает публичные настройки: выбранного поставщика LLM, адрес сервиса, параметры модели и доступность функций. Секретный ключ в ответ никогда не включается.

### `PUT /api/config`

Изменяет настройки и, при явной передаче, секрет модели. Ключ записывается в Windows Credential Manager через `keyring`, а не в JSON-конфигурацию. Ответ также не раскрывает секрет.

### `GET /api/health`

Проверяет готовность локального сервиса и фонового worker. Ответ содержит статус готовности без персональных данных и без технических секретов.

## Локальные данные и безопасность

Расположение определяется через `platformdirs`:

- настройки: `%APPDATA%\TriemaDeid\config.json`;
- база: `%LOCALAPPDATA%\TriemaDeid\app.db`;
- файлы задач: `%LOCALAPPDATA%\TriemaDeid\jobs\<job_id>\`;
- логи: `%LOCALAPPDATA%\TriemaDeid\logs\`.

Каталоги задач подлежат автоматической очистке по настроенному сроку хранения. Логи не должны содержать исходные персональные данные, содержимое документов, ключи API или токены. Секрет GigaChat и других провайдеров хранится только в Credential Manager.

## Структура проекта

```text
app/                 FastAPI: приложение, маршруты, API-схемы и DI
core/                Независимая доменная логика
  extractors/        Извлечение из DOCX, XLSX, PDF и будущий OCR
  detectors/         Правила, LLM-поиск и определение ролей сторон
  redaction/         Применение замен для DOCX, XLSX и PDF
  report/            JSON-отчёт об обработке
llm/                 AsyncBaseLLMClient и адаптеры поставщиков моделей
storage/             SQLite-репозиторий и локальные файлы задач
tests/               Модульные, интеграционные и сквозные тесты
```

## Запуск и сборка

Рабочая среда разработки — Windows с Python 3.12, Node.js и pnpm, установленными WebView2 и Tesseract при включении будущей OCR-функции. Backend и frontend запускаются локально; внешнее сетевое подключение нужно только выбранному облачному поставщику LLM.

Для дистрибутива применяется PyInstaller. Ранние сборки создаются в режиме `--onedir`; переход к `--onefile` возможен только после проверки размера, времени запуска и корректности работы WebView2. Docker не является способом запуска или поставки MVP.

## Тестирование и качество

- `pytest`, `pytest-asyncio` и `httpx` покрывают модели, извлечение, детектирование, маскирование, LLM-адаптеры и HTTP-сценарии.
- Эталонные PDF, DOCX и XLSX с ручной разметкой задают критерии приёмки: найдены нужные сущности, сохранён формат документа, изменения подсвечены, отчёт согласован с результатом.
- Vitest проверяет API-клиент React и основные состояния: загрузку, обработку, вопросы, ошибку и готовый результат.
- Ruff обеспечивает единые базовые проверки и форматирование Python-кода.

## Ограничения MVP

- Один локальный worker обрабатывает задачи последовательно; Redis и распределённая очередь не используются.
- OCR сканированных PDF не входит в базовую поставку.
- Качество распознавания сущностей зависит от структуры документа, выбранных типов данных и подключённой модели; подсветка и отчёт предназначены для обязательной ручной валидации.
- Результат сохраняет исходный формат файла, но точность сохранения форматирования зависит от возможностей соответствующей библиотеки и особенностей документа.
