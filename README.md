# DockMask

**DockMask** — локальный AI-помощник для обезличивания конфиденциальных данных в тендерных документах. Решение создано для кейса АО «Триема» на хакатоне «Цифроземье 2026»: пользователь загружает документ, выбирает чувствительные типы данных и получает обезличенную копию с подсветкой замен и отчётом для проверки.

## Задача заказчика

**Заказчик:** АО «Триема», ИНН 3662103003 — оптовая торговля электронными компонентами, деталями и запасными частями.

В договорах, счетах, актах, финансовых отчётах и коммерческих предложениях есть реквизиты и сведения, которые нельзя передавать дальше без обработки. Ручная проверка занимает время и легко пропускает фрагменты в таблицах, сканах и документах произвольной структуры.

DockMask готовит копию документа к безопасной передаче: находит выбранные данные, заменяет их понятными маркерами, выделяет каждую замену и сохраняет исходник без изменений.

## Возможности

- Принимает PDF, DOCX и XLSX, включая документы с таблицами.
- Обрабатывает PDF с текстовым слоем, сканы и смешанные PDF. Для изображений используется встроенный локальный OCR Tesseract с русским и английским языками.
- Находит ФИО, организации, адреса, суммы, ИНН, КПП, ОГРН, телефоны, электронную почту, расчётные счета, БИК и номера договоров.
- Совмещает точные правила для реквизитов и AI-анализ для контекстных сущностей.
- Определяет сторону организации или физического лица: поставщик, покупатель или неизвестно. Если контекста недостаточно, задаёт пользователю уточняющий вопрос.
- Заменяет данные на стабильные маркеры, например `[[ОРГАНИЗАЦИЯ_1]]`, и визуально выделяет их в итоговом документе.
- Возвращает обезличенный документ в исходном формате, а также JSON-, CSV- и XLSX-отчёты со списком замен.
- Поддерживает GigaChat, локальные модели через Ollama/vLLM, совместимый OpenAI API, OpenAI и Anthropic. Провайдера можно заменить без изменения бизнес-логики.

## Как пользоваться

1. Запустите `DockMask.exe`.
2. В настройках выберите режим анализа. Для GigaChat укажите ключ и модель; локальный режим не требует облачного ключа.
3. Загрузите PDF, DOCX или XLSX и отметьте данные, которые нужно обезличить.
   В поле «Подписи на масках» выберите полные маркеры, короткие (`[ОРГ_2]`) или
   заливку без надписей. Для узких полей PDF удобнее короткие подписи. Выбор сохраняется
   в задании, включая продолжение после уточняющих вопросов; отчёт сохраняет полные идентификаторы.
4. Запустите обработку. Если приложение не смогло определить роль стороны, ответьте на вопрос в интерфейсе.
5. Просмотрите список замен и скачайте обезличенный документ или отчёт.

Исходный файл не перезаписывается. Подсветка в результате нужна для ручной валидации: перед передачей документа пользователь видит, что именно изменилось.

PDF-маски привязаны к символам и строкам: многострочная сущность закрывается на каждой
строке, одна подпись размещается по центру самой широкой части. Размер подписи ограничен
размером маски, поэтому длинный маркер в очень узком поле всё ещё будет мелким.
Подтверждённые названия, ФИО, адреса и суммы дополнительно ищутся по всему документу,
включая повторы с изменёнными пробелами и переносами строк.

## Результат

| Артефакт | Назначение |
| --- | --- |
| Обезличенный PDF, DOCX или XLSX | Копия исходника с маскировочными маркерами и подсветкой замен. |
| JSON-отчёт | Машиночитаемый список найденных и применённых замен. |
| CSV- и XLSX-отчёты | Табличная проверка сущности, маски, источника, уверенности и расположения. |
| Предпросмотр | Краткое представление результата в приложении до сохранения файла. |

## GigaChat, локальность и защита данных

GigaChat помогает находить контекстные сущности, которые сложно описать регулярными выражениями, и определяет роль стороны в документе. Реквизиты с устойчивым форматом — ИНН, телефон, e-mail, БИК и другие — дополнительно ищутся локальными правилами и проверками.

При выборе GigaChat, OpenAI или Anthropic текстовые блоки, нужные для анализа, передаются выбранному провайдеру. В режиме без облачной LLM приложение работает локально; с заранее установленной моделью через Ollama или vLLM обработка может быть полностью офлайн. API-ключи хранятся в Windows Credential Manager, не возвращаются интерфейсу и не записываются в логи.

Приложение запускает сервис только на `127.0.0.1`: документ не публикуется в сети. Локальные задания и база находятся в `%LOCALAPPDATA%\Triema\DockMask`; технические логи не содержат текст документов, найденные значения или ключи.

## Для жюри

Решение закрывает обязательные пункты кейса АО «Триема»: локальная работа, PDF/DOCX/XLSX, сохранение структуры и формата, подсветка замен, отчёт, уточнение роли стороны, OCR сканированных PDF и сменяемый слой моделей.

Главный сценарий демонстрации: загрузить договор или коммерческое предложение, выбрать реквизиты и организацию, получить выделенную обезличенную копию и сверить её с отчётом. Для GigaChat заранее настройте ключ в разделе настроек; для демонстрации без сети выберите локальный режим или подключённую локальную модель.

В репозитории есть автоматические проверки backend, frontend и сквозных сценариев DOCX/XLSX/PDF. Сборочный скрипт запускает их до упаковки и затем проверяет готовый EXE, включая OCR и TLS-настройки GigaChat.

## Быстрый запуск EXE

1. Скачайте `DockMask.exe` из Releases или возьмите `output/exe/DockMask.exe` после локальной сборки.
2. Запустите файл двойным щелчком. Установка и отдельная папка с Tesseract не требуются.
3. Если Windows SmartScreen показывает предупреждение, используйте только файл из доверенного релиза проекта: EXE пока не подписан коммерческим сертификатом.

При первом запуске OCR-компонент распаковывается во внутренний кэш пользователя. В последующих запусках повторная подготовка не требуется.

## Сборка Windows EXE

### Требования

- Windows 10/11;
- Node.js 22+ с Corepack;
- [uv](https://docs.astral.sh/uv/);
- интернет при первой сборке, если пакеты и OCR runtime отсутствуют в локальном кеше.

### Команда

Откройте PowerShell в корне репозитория:

```powershell
.\scripts\build_windows.ps1
```

Скрипт устанавливает закреплённые frontend-зависимости, запускает frontend-тесты и проверку типов, готовит Tesseract OCR, запускает backend-тесты, Ruff и проверку lockfile, собирает PyInstaller-пакет и выполняет его самопроверку. Готовый единственный файл появится здесь:

```text
output\exe\DockMask.exe
```

Глобально устанавливать `pnpm` не нужно: скрипт использует Corepack и закреплённую версию из `frontend/package.json`.

### Сборка через GitHub Actions

1. Откройте **Actions → Build Windows Release → Run workflow**.
2. Укажите новую версию, например `0.1.0`.
3. После завершения workflow скачайте `DockMask.exe` из **Releases**.

Workflow не перезаписывает существующий тег или релиз; диагностический artifact хранится 14 дней.

## Устройство решения

```text
React + TypeScript интерфейс
            │
            ▼
Локальный FastAPI-сервис и очередь обработки
            │
 ┌──────────┼──────────┐
 ▼          ▼          ▼
Извлечение  Детекторы   Redaction и отчёты
PDF/DOCX/   правила +   PDF/DOCX/XLSX
XLSX/OCR    LLM
```

| Компонент | Роль |
| --- | --- |
| `frontend/` | Интерфейс загрузки, настройки модели, уточняющие вопросы и просмотр результата. |
| `app/` | Локальное API, управление задачами, настройками и desktop-окном. |
| `core/` | Извлечение структуры, поиск сущностей, определение сторон, маскировка и отчёты. |
| `llm/` | Адаптеры GigaChat и других провайдеров. Подробности — в [`llm/README.md`](llm/README.md). |
| `storage/` | Локальное хранение метаданных задач в SQLite. |
| `tests/` | Модульные, API-, frontend- и сквозные проверки. |

## Разработка и проверка

Основной production-путь — команда сборки выше. При доработке можно отдельно выполнить:

```powershell
uv run pytest -q tests
uv run ruff check .
corepack pnpm --dir frontend test -- --run
corepack pnpm --dir frontend typecheck
```

Не добавляйте в Git реальные документы, их фрагменты, API-ключи или OAuth-токены. Для тестов используйте синтетические данные.

## Ограничения MVP

- Подсветка и замены ускоряют ручную проверку, но не отменяют её.
- Качество OCR зависит от читаемости скана.
- Для облачной модели нужны интернет и действующий ключ выбранного провайдера.
- Одновременно обрабатывается одна задача: это осознанный выбор в пользу простого локального MVP.
