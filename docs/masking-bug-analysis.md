# Проверка маскирования договора и счёта

Исправления проверены на двух предоставленных синтетических документах. В локальных регрессиях и при повторном применении сохранённых ответов GigaChat последняя версия конвейера скрывает все **73 размеченных вхождения**: 35 в договоре и 38 в счёте. В результирующем извлечённом тексте эти исходные значения отсутствуют. Это результат на данном наборе примеров, а не гарантия полноты на любых документах.

## Разделение причин

| Симптом | Установленная причина | Исправление |
|---|---|---|
| ИНН и ОГРН отсутствуют в отчёте | Правила были подключены, но отбрасывали неверную контрольную цифру. Все четыре номера примера не проходят её проверку. | Явно подписанные значения подходящей длины маскируются; контрольная цифра фиксируется в диагностике. |
| Телефон менеджера PDF пропущен | Регулярное выражение не принимало перенос после кода оператора. | Переносы и пробелы поддерживаются с сохранением исходных смещений. Разные ячейки не склеиваются. |
| Л/с и К/с не скрыты | Поддерживался только расчётный счёт. | Расчётные, корреспондентские и лицевые счета входят в существующую категорию `bank_account`. |
| Суммы и цены пропущены | Поиск зависел от модели; PDF передавался без связей денежных ячеек с заголовками. | Правила сумм с валютой и прописью, денежные столбцы по структуре таблицы, дополнительный контекст для модели. |
| PDF-адреса пропущены | Общий резервный детектор требовал метку «адрес:». Отдельного PDF-детектора адресов не было. | Добавлены типовые адреса без метки; точные переносы сохраняются. |
| Подписи и названия распознаны неполно | Недостаточные резервные правила и отсутствие структуры в запросе. | Инициалы в обоих порядках, полные названия, бюджетные учреждения, явные сокращения в скобках. |
| Роли сторон перепутаны | Уже назначенная моделью роль не сверялась с локальными фактами; соседство блоков подменяло структуру. | Приоритет явных формулировок и столбцов; отдельный контекст банковских реквизитов и подписей счёта. |
| Ковалёва связана с поставщиком | При второй конструкции «в лице» выбиралась предыдущая найденная организация. | Представительство ограничено соответствующей конструкцией. |
| Индикатор остаётся на первом шаге | Сервер сообщал условные 5/70/100%, интерфейс вычислял шаг из процента. | Состояния этапов сохраняются в SQLite и передаются напрямую. |
| Лишние уточнения | Неизвестная роль блокировала маскирование, хотя результат от неё не зависел. | Вопросы только о спорных масках; неизвестная роль и неверная контрольная цифра сами по себе не блокируют обработку. |

## Реальные прогоны GigaChat

Проверена `GigaChat-3-Pro`, температура 0.1, лимит ответа 4096 токенов. Три варианта запроса, по три прогона на документ. Разбиение на группы одинаковое внутри сравнения. Проверялись четыре LLM-категории: ФИО, организации, адреса, суммы. Числовые реквизиты проверялись отдельно в конвейере.

| Документ | Вариант | Полные ответы | Покрытие в полных ответах |
|---|---|---|---|
| DOCX | Исходный промпт | 2 из 3 | 12/16 и 10/16 |
| DOCX | Уточнённый промпт | 2 из 3 | 11/16 и 11/16 |
| DOCX | Промпт и структура | 2 из 3 | 13/16 и 13/16 |
| PDF | Исходный промпт | 2 из 3 | 6/24 и 6/24 |
| PDF | Уточнённый промпт | 3 из 3 | 15/24, 15/24 и 10/24 |
| PDF | Промпт и структура | 2 из 3 | 14/24 и 14/24 |

Пять ответов обрезаны по лимиту; они не включены в показатели полноты успешных прогонов. Изолированное уточнение промпта не повысило полноту на DOCX. Структурный контекст помог в этих примерах, но модель всё равно оставляет пропуски. Три прогона не позволяют делать статистические выводы о качестве модели в целом.

В сохранённых ответах подтверждены ошибки модели: перевод ФИО из родительного падежа в именительный, включение даты в адрес, контактов в категорию адресов, разделителя `/` в ФИО. Точное сопоставление с исходником обоснованно отклоняет изменённые строки; нечёткое сопоставление для координат маски не применяется. Подтверждённые правила компенсируют пропуски; разделители подписей и составные названия уточняются по точным локальным границам. Предполагаемый адрес с датой выносится на уточнение.

Оба полных сетевых прогона завершились `done` (33 и 38 замен; составное название с сокращением может считаться одной заменой). Затем те же ответы воспроизведены на последней версии постобработки без новых запросов: 35 и 38 замен, покрытие 73/73. Разница в DOCX связана с разделением двух составных названий на полную и сокращённую формы. Проверены PDF и двухстраничный DOCX, экспортированный установленным Word: маски не повреждают соседние данные. XML проверенного DOCX совпадает с результатом воспроизведения.

Первоначальное сообщение о замене «Генеральный директор» отсутствовало в приложенных JSON. Добавлена защита и отрицательный тест для должности без ФИО; исторический инцидент не объявляется воспроизведённым.

## Интерфейсы и диагностика

- `GET /api/jobs/{id}` дополнен `stages`: идентификатор этапа, состояние, подэтап, время начала и окончания. Старое поле `progress` сохранено; ошибка и отмена не выставляют успешные 100%.
- Пять этапов: `extract`, `detect`, `clarify`, `redact`, `report`. Ожидание модели и повторы отражаются в `detail`. После ответа пользователя завершённые этапы не сбрасываются.
- Вопросы дополнены `kind`, `reason`, `contexts`; решения маскирования — `mask`/`keep`. Старые ответы `supplier`/`buyer`/`unknown` поддерживаются для ожидающих заданий. Повторяющиеся подтверждённые сущности получают общий вопрос.
- Активное задание и выбранные ответы восстанавливаются после повторного открытия интерфейса. В браузерное хранилище записываются ID задания, сведения о файле и решения; текст документа и ключи туда не добавляются.
- `GET /api/jobs/{id}/diagnostics.json` возвращает отдельную диагностику: версии, модель, выбранные категории, состав запросов по ID блоков, количество кандидатов, причины отклонения, применение масок. Обычный JSON замен совместим с прежним форматом.
- Диагностика не содержит исходных значений, ключей или HTTP-заголовков. Фиксированная оценка адаптера `0.8` явно не трактуется как калиброванная вероятность.
- Если принятая маска не применилась, итоговый документ не публикуется; задание завершается с `redaction_incomplete`.

## Воспроизведение

Итоговая офлайн-проверка: `python -m pytest tests -q --ignore=tests/test_gigachat_integration.py` — 204 теста и 56 подслучаев прошли. Отдельный старый сетевой integration-тест в ограниченной среде завершился ошибкой подключения OAuth; реальные разрешённые сетевые проверки выполнены отдельным скриптом, результаты приведены выше. Запуск pytest ограничен каталогом `tests`, чтобы не собирать архивные тесты из временных каталогов.

Файлы и разметка находятся в `tests/fixtures/masking`. Офлайн-проверки: `tests/test_masking_regression.py` и `tests/test_progress_and_answers.py`. Они включают отрицательные примеры, независимые ячейки, сохранение процентов и количеств, продолжение без повторного LLM-вызова, отмену, ошибку и восстановление состояния.

`python -m scripts.check_masking_regression` читает тестовый ключ из stdin, сохраняет только синтетические запросы и ответы в `output/masking-regression` и продолжает серию после обрезанного ответа. Уже записанные прогоны пропускаются; для нового независимого эксперимента нужен отдельный чистый каталог результатов.

`python -m scripts.masking_quality` оценивает сохранённые ответы по непересекающейся разметке. `python -m scripts.replay_masking_regression` проверяет текущую постобработку с сохранёнными ответами, включая при необходимости тестовые решения по эталонной разметке. Эти решения не являются автоматической политикой рабочего приложения.
